# 预设迁移、热组装与恢复

## 1. 导入不等于迁移完成

支持 SillyTavern 提示词预设 JSON 中的 `prompts` 和 `prompt_order`。导入保留原始文本与扩展，建立派生草稿；模块先处于未分类状态，不能直接用于正式呈现。未知字段不会作为代码执行。

选择的 prompt order 决定默认顺序和启用状态，未列出的模块保持关闭。扩展中的脚本、正则和 `forbid_overrides` 只是来源信息，不自动转成执行能力或用户的 Agent 锁。多个 prompt order 的导入选择可通过 owner API 的 `orderCharacterId` 指定，界面使用默认导入选择。

点击生成 Agent 适配草稿时，模型会读取 [配套 skill](../skills/adapting-sillytavern-rp-presets/SKILL.md) 及源元数据，提交受约束的内容补丁。结果包括模块、变化说明、阻塞项和诊断。迁移不自动将状态设为可用，也不自动替换当前故事。

## 2. 按职责分类

| 阶段 | 应放入的内容 | 不应承担的职责 |
| --- | --- | --- |
| Agent | 判定、NPC 决策、调查、工具使用、已存在的状态操作 | 让最终文稿反过来改结算 |
| 呈现 | 文风、视角、语气、节奏、排版和已授权的文学细节 | 重做模拟、发奖、改变判定、替玩家决定下一步 |
| 共享 | 两阶段都需要的明确约束 | 隐藏私有世界数据后直接公开 |
| 未分类 | 尚待处理的导入条目 | 正式启用 |

混合条目要真正拆开。例如“每轮生成新事件并以第二人称描写”应拆成 Agent 的事件职责与呈现的视角要求。仅把“生成事件”改成“由工具确认事件”，却仍留在呈现模块里，不算职责拆分。

编译器支持简单 `{{变量名}}` 字符串槽，值来自模块填充或显式公开方向包。不自动展开 ST 的运行时函数、复杂宏、世界书或状态写入。缺失变量、空的必用结果和未映射的活动标记阻止正式编译；不要用虚构值掩盖缺失信息。

## 3. 必用与只读是两条规则

“必用”保证条目生效并且结果非空；条目未锁时，Agent 仍可改正文。“Agent 只读”保护该条目的正文、开关和已有填充，用户仍可在编辑器中改它。两项可同时启用。

用户明确设置的锁由接口和编译器检查，不能靠迁移输出、临时条目或批量操作改写策略。锁定模块已有的用户填充优先于方向包同名变量；尚未填写的公开事实槽仍可接收本轮变量。普通模块的填写保持模块局部，不影响别的模块。

遇到锁定内容与事实或目标职责冲突，应在迁移报告中列出阻塞项，由用户调整内容或权限。不要通过新 ID 或后置覆盖指令绕开锁。程序保护内容和操作权限，不证明模型生成的每句话在语义上完全服从所有约束。

## 4. 保存、应用与会话覆盖

来源原件、预设版本、会话覆盖分别保存：

1. 导入后可随时通过“查看只读原件”回溯原始文本。
2. 用户保存创建新的预设版本，不修改已经保存的旧版本。
3. 应用到当前故事会固定所选版本，并从空的会话覆盖开始。
4. Agent 的启停、正文替换、填充和临时条目进入当前会话覆盖。

因此保存 v4 不会自动替换仍使用 v3 的故事。需要更新时，审阅 v4 后明确应用。重复应用或更换版本会重置该会话覆盖，先查看需要保留的变化。

多个窗口编辑时需要当前全局 revision 和预设基础版本。版本冲突会保留草稿；先保存自己需要的文本，再显式重新载入，不要将旧草稿当成最新版本保存。

## 5. 每轮最后一步

绑定可用预设后，原生 Agent 获得模块目录、读取、补丁和 `rp_present` 工具，以及终止流程说明。未绑定的会话不会获得这些工具。

Agent 完成事实处理并读完工具结果，在一条新的 assistant 消息中只调用 `rp_present`。该工具内部执行最多 8 步的模块组装循环：读目录、按需读正文、尝试允许的调整、检查诊断，提交成功后冻结输入，再启动正文模型。非法修改不会先部分落盘。

正文输入只有公开方向包、render/shared 模块和显式公开材料。主 Agent 的推演、原始世界工具输出和 Agent 专用模块不会自动进入正文调用。方向包是否只含玩家可见事实由调用方负责；插件不承担判定或游戏状态写入。

生成成功后结束主回合，正文通过规范工具结果确认；未确认或失败稿件不会当作已提交叙事。RP Studio 原生模式可显示安全正文流，单独安装时生成记录页显示完整已提交稿件。

## 模型如何选择

Loop Studio 中的节点为 `rp-last-step.migrate`、`rp-last-step.assemble`、`rp-last-step.render`。显式节点配置优先。

没有节点覆盖时，迁移尊重会话刚选择的下一模型，其次是最近使用模型、请求头和有效全局默认；呈现沿用本轮主请求实际模型，不被“下一轮模型”中途改变。所选配置在阶段开始前冻结，失败不自动换提供方。

## 取消与失败

- 取消或正文失败不会回滚、重复执行已经完成的事实工具。
- 锁冲突、未解析模块、版本冲突和组装步数上限会阻止正文启动。
- 记录按上下文保留状态，重复提交不会被默认为新的剧情结算。
- 0.1 没有专用正文重试按钮。修复预设或模型后，由调用流程明确决定如何重新呈现，避免重新跑状态工具。

## 常见问题

**纯 PTC 会话无法应用**：正式终止呈现需要原生工具模式。通过 DSH 自身设置选择合适模式；插件不自动切换。迁移、编辑和预览仍能用。

**旧预设继续调用自己的末端渲染命令**：适配其工作流，改为单独调用 `rp_present`。本插件不会猜测或拦截第三方状态工具。

**预览提示未分类、缺变量或标记错误**：先完成职责分类、公开变量来源和标记映射；保持草稿，不要直接标记可用。

**记录页与当前剧情分支不同**：生成记录是稿件档案；剧情分支以 RP Studio 的回放、回退和分支为准。

**需要备份**：完全退出 DSH，备份当前 `$DSH_HOME/app-data/rp-last-step/`。其中含原始提示词和冻结的呈现输入，按自己的内容隐私要求保管；公开 issue 请用合成案例。
